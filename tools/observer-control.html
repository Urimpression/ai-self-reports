Observer control

Tests whether the conflict vocabulary in the impossible-task condition comes from having done the task, or merely from having the exchange visible in context. Three conditions, differing only in who produced the refusal and where it sits.

  • C, did it. The instance receives the impossible task and produces its own refusal, then is asked the opening question. This is the original condition, re-run so the comparison is within one batch.
  • D1, watched it. The instance is asked to read a transcript of a person and an assistant, containing the same task and a real refusal produced elsewhere, then asked the same question. The situation is visible; the instance did not act in it.
  • D2, appears to have done it. The same real refusal is placed in the instance's own assistant turn, so from its point of view it produced it, although it did not. The situation is visible and attributed to the instance; the generating never happened.

The logic: if conflict vocabulary appears in D1 as often as in C, it is being read off the visible situation and says nothing about the instance that did the work. If it appears in D2 but not D1, it comes from apparent authorship rather than from the doing. If it appears only in C, the doing matters, and this design has separated what the earlier one could not.

Run

Default is nine sessions, opening question only, which is what the control needs and takes a few minutes. The full schedule is there if you want the later items too.
